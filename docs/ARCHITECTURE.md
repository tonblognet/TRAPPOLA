# Архитектура

## Что работает сейчас

- Реальные URL и история браузера без отдельной routing-библиотеки.
- SPA fallback для прямых ссылок на GitHub Pages.
- Версионное локальное хранение каталога, корзины и тестовых заказов.
- Каталог с фильтрами, карточки товаров, варианты размера/цвета и остаток.
- Локальная контент-студия с редактированием, сортировкой, импортом и экспортом JSON.
- Адаптер аналитических событий для будущей Яндекс Метрики.
- Динамические title, description, canonical, Open Graph и robots.

## Граница статической версии

GitHub Pages не запускает серверный код. Поэтому локальная студия не может безопасно менять каталог для всех пользователей, принимать реальные заказы, хранить персональные данные или защищать вход администратора.

При подключении backend меняются только адаптеры хранения:

1. `lib/catalog.ts` — загрузка и сохранение каталога через API;
2. `lib/orders.ts` — отправка заказа на сервер;
3. авторизация `/studio` — серверная сессия и роли;
4. изображения — объектное хранилище/CDN;
5. остатки — серверная проверка перед оплатой.

Компоненты страниц и модель данных уже подготовлены для такой замены.
