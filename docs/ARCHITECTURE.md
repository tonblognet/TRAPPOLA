# Архитектура

## Два режима одной витрины

- `VITE_BACKEND_MODE=demo`: GitHub Pages, локальный каталог и тестовые заказы в браузере.
- `VITE_BACKEND_MODE=api`: VPS, PostgreSQL, настоящая админка и серверные заявки.

GitHub Pages не получает секреты и не отправляет персональные данные. Production-сборка обслуживается Node.js с того же домена, поэтому API и cookie остаются same-origin.

## Сервер

- Express 5 и Zod для API и проверки входных данных;
- PostgreSQL 17 и SQL-миграции;
- транзакционная проверка и уменьшение остатков;
- снимок названия, артикула и цены в составе заказа;
- администраторские сессии со случайным токеном, хешем токена в БД, HttpOnly-cookie и CSRF;
- ограничение частоты входа и оформления заявок;
- PNG/JPEG/WebP-загрузки с проверкой сигнатуры файла и отдельным persistent volume.

## Инфраструктура

Docker Compose поднимает `app`, `db` и `caddy`. PostgreSQL не публикуется наружу. Caddy получает TLS-сертификат и проксирует сайт/API. Persistent volumes сохраняют базу, изображения и сертификаты между обновлениями. `ops/backup.sh` создаёт дампы PostgreSQL с ротацией 30 дней.

## Оставшиеся интеграции

Платёжный провайдер, касса, доставка, доменная почта и Метрика требуют договоров, реквизитов или ключей. Они не эмулируются и не хранятся в клиентской сборке.
