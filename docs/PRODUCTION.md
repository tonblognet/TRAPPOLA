# TRAPPOLA: запуск магазина на VPS

GitHub Pages остаётся демонстрационной витриной. Реальная версия запускается на VPS и состоит из трёх контейнеров:

- `app` — сайт, API и защищённая админка;
- `db` — PostgreSQL с товарами, остатками, заказами и настройками;
- `caddy` — HTTPS-сертификаты и проксирование домена.

## Что уже реализовано

- каталог и варианты товара по размеру/цвету;
- остатки с транзакционным списанием при оформлении заявки;
- заказы и их статусы;
- защищённый вход администратора, HttpOnly-cookie, CSRF и ограничение попыток входа;
- редактирование товаров, вариантов и изображений;
- реквизиты продавца в настройках;
- миграции базы, healthcheck, Docker Compose, HTTPS и резервные копии;
- безопасный режим заказа без списания денег до выбора эквайринга.

## 1. Подготовка VPS

Подойдёт Ubuntu 24.04 на VPS с 2 vCPU, 2–4 ГБ RAM и диском от 30 ГБ. Для персональных данных покупателей выбирайте сервер, физически расположенный в России. Установите Docker Engine и Compose по официальной инструкции Docker.

Откройте входящие TCP-порты `22`, `80`, `443` и UDP-порт `443`. PostgreSQL-порт `5432` наружу не открывайте.

## 2. DNS

В REG.RU создайте записи:

- `A` для `@` → публичный IPv4 VPS;
- `A` для `www` → тот же IPv4 VPS.

Удалять домен или почтовые MX-записи не нужно. После обновления DNS Caddy сам получит HTTPS-сертификат.

## 3. Конфигурация

```bash
git clone https://github.com/tonblognet/TRAPPOLA.git
cd TRAPPOLA
cp .env.production.example .env.production
chmod 600 .env.production
```

Заполните `.env.production`. Пароль PostgreSQL должен быть длинным и случайным. В `DATABASE_URL` специальные символы пароля нужно URL-кодировать; проще использовать пароль из букв и цифр длиной 32+ символа.

`.env.production` запрещено добавлять в Git.

## 4. Первый запуск

```bash
docker compose --env-file .env.production up -d --build
docker compose --env-file .env.production ps
docker compose --env-file .env.production logs app --tail=100
```

Миграции запускаются приложением автоматически и не удаляют существующие данные.

Создайте администратора, передав значения только этой команде:

```bash
docker compose --env-file .env.production exec \
  -e ADMIN_EMAIL='owner@example.com' \
  -e ADMIN_PASSWORD='уникальный-пароль-длиной-16-символов-или-больше' \
  -e ADMIN_NAME='Елена' app \
  node server-dist/bootstrap-admin.mjs
```

Пароль не сохраняется в `.env.production` или истории Git. Вход: `https://trappola.ru/admin`.

Чтобы перенести шесть текущих демонстрационных товаров в базу:

```bash
docker compose --env-file .env.production exec app node server-dist/seed-catalog.mjs
```

Импорт намеренно создаёт товары скрытыми и с нулевыми остатками. Елена сможет проверить фото, размеры и реальные остатки в админке, затем опубликовать товары.

## 5. Обновление

```bash
git pull --ff-only
docker compose --env-file .env.production up -d --build
docker image prune -f
```

Перед обновлением сделайте резервную копию.

## 6. Резервные копии

```bash
chmod +x ops/backup.sh ops/restore.sh
./ops/backup.sh
```

Скрипт создаёт дамп базы и отдельный архив загруженных изображений, хранит их локально 30 дней. Для реальной отказоустойчивости ежедневно копируйте каталог `backups` во внешнее российское S3-совместимое хранилище или на второй сервер. Пример cron в `crontab -e`:

```text
15 3 * * * cd /opt/TRAPPOLA && ./ops/backup.sh >> /var/log/trappola-backup.log 2>&1
```

Восстановление требует явного подтверждения:

```bash
./ops/restore.sh ./backups/trappola-YYYYMMDDTHHMMSSZ.dump
./ops/restore-uploads.sh ./backups/trappola-uploads-YYYYMMDDTHHMMSSZ.tar.gz
```

## Что требует решений и доступов Елены

- реальные фотографии, описания, цены, размеры и остатки;
- подтверждение ИП и юридических документов;
- договор с российским эквайрингом и его секретные ключи;
- служба доставки и её API-ключи;
- доступ к REG.RU для DNS и доменной почты;
- идентификатор Яндекс Метрики.

Эквайринг нельзя безопасно «включить заранее»: итоговая схема зависит от банка, статуса продавца, чеков и онлайн-кассы. До этого сайт принимает заявку без списания денег.
